# Смена-бот

Telegram-бот для расписания смен сотрудников: регистрация, просмотр своего графика, заявки на изменение смены, управление филиалом и ролями.

## Роли

| Роль | Что может |
| :--- | :--- |
| `worker` — Работник | смотреть своё расписание, просить изменить смену |
| `manager` — Менеджер, `branch_admin` — Управляющий | расписание филиала, одобрять заявки (кроме своих), назначать смены, делать сотрудников своего филиала неактивными и возвращать в работу |
| `superadmin` — Администратор (не больше двух) | всё выше для любого филиала + подтверждение новых пользователей, назначение ролей, перевод в другой филиал, рассылка, пауза бота |

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # вписать BOT_TOKEN и FIRST_SUPERADMIN_ID
python3 bot.py
```

`FIRST_SUPERADMIN_ID` — ваш Telegram ID (узнать можно у @userinfobot). При старте этот пользователь становится Администратором.

Важно: запускайте **одну** копию бота на один токен. Две копии (например, на ноутбуке и на сервере) делят сообщения между собой, и часть пользователей «теряется».

Лог пишется в консоль и в `bot.log` (ротация: 1 МБ × 5 файлов), база — `bot_data.db`, начатые диалоги — `bot_states.pkl` (все рядом с `bot.py`, в git не попадают). Telegram ID в логах не пишутся: вместо них метка из 8 символов. Чтобы метки не менялись между запусками, задайте в `.env` случайную строку `LOG_SALT` (например, `python3 -c "import secrets; print(secrets.token_hex(16))"`); без неё бот сгенерирует соль сам и предупредит в логе.

## Регистрация и доступ

1. Новый пользователь нажимает `/start` и вводит ФИО → выбирает филиал → вводит должность.
2. Бот отвечает «Заявка на доступ отправлена, ждите подтверждения». Пока заявка не рассмотрена, работают только `/start`, `/help` и `/cancel`; на всё остальное — «Ваша заявка ещё на рассмотрении».
3. Администраторам приходит карточка с кнопками «✅ Подтвердить / ❌ Отклонить». После подтверждения там же появляются кнопки ролей (по умолчанию — Работник). Второе нажатие (или нажатие второго Администратора) — «Заявка уже обработана».
4. Пользователю приходит решение. Подтверждённый получает меню, отклонённый становится неактивным.

Статус пользователя: `pending` — ждёт подтверждения, `active` — работает, `inactive` — доступ закрыт.

## Сотрудники: неактивный, возврат в работу, перевод

Кнопка «👥 Сотрудники» (Администратор сначала выбирает филиал) → список → карточка сотрудника: ФИО, должность, филиал, роль, статус.

- **🚫 Сделать неактивным** (уволился, долго отсутствует) — руководитель своего филиала или Администратор. Себя отключить нельзя; Администратора отключает только Администратор, последнего активного — нельзя. Неактивный на любое действие получает «Доступ закрыт, обратитесь к руководителю», не виден в расписании филиала и списках, не получает заявки, рассылки и оповещения о паузе. Его ожидающие заявки закрываются, смены и история остаются в базе.
- **✅ Вернуть в работу** — в том же списке кнопка «🗂 Показать неактивных» → карточка.
- **🗓 Изменить смену** — тот же сценарий, что «🛠 Изменить расписание сотрудника».
- **🏢 Перевести в филиал** — только Администратор. Записи со старым тестовым филиалом «Гугл» (и первый Администратор с филиалом «—») — в списке «❓ Филиал не из списка» при выборе филиала.

## Как пользоваться

- **Расписание** («📅 Моё расписание», «🏢 Расписание филиала») показывается на 14 дней от сегодня. Длинное расписание приходит несколькими сообщениями.
- **Администратор** перед «🏢 Расписание филиала», «📥 Запросы на изменение», «🛠 Изменить расписание сотрудника» и «👥 Сотрудники» выбирает филиал кнопкой.
- **Заявки** получают активные Менеджеры и Управляющие филиала, а если их нет — Администраторы. Свою заявку руководитель не получает и решить не может («Нельзя решать собственную заявку») — её решает другой руководитель или Администратор. Если доставить заявку не удалось, работник увидит это сразу.
- **Рассылка**: после текста бот показывает предпросмотр с кнопками «✅ Отправить / ❌ Отмена», в конце — сколько доставлено и сколько нет.
- **Пауза** останавливает бота для всех, кроме Администраторов, в том числе посреди начатого ввода.
- **Отмена**: `/cancel` или «❌ Отмена» в любой момент. На шагах ввода кнопки меню и команды не принимаются — бот напомнит, что ждёт ответ. ФИО и должность — до 64 символов.

## Даты и время смен

Дата вводится как `ДД.ММ` (или `ДД.ММ.ГГГГ`), время — `08:00 - 20:00` или `Выходной`. Неверный ввод бот не сохраняет и просит ввести заново. В базе дата хранится как `ГГГГ-ММ-ДД`, чтобы расписание правильно сортировалось. На одного сотрудника — одна смена в день.

При первом запуске новой версии старая база обновляется сама (`PRAGMA user_version`):

- **1** — даты `ДД.ММ` переводятся в новый формат, дубли смен удаляются (остаётся последняя запись). Год для старых дат — ближайший ко дню обновления.
- **2** — у пользователей появляется статус (`users.status`); все, кто уже был в базе, — `active`.

Перед обновлением бот сам кладёт копию базы рядом: `bot_data.db.bak-ГГГГММДД`.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

Тесты запускают настоящие обработчики бота на временной базе, с подменённым Telegram API — в Telegram ничего не отправляется.
